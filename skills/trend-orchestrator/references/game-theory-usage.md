# Game Theory for Crypto 集成指南

> 代币经济建模与博弈分析——激励机制评估、MEV 策略、流动性博弈、设计缺陷检测。

## 适用场景

| 场景 | 分析重点 |
|------|----------|
| 新项目评估 | 代币经济模型是否可持续（庞氏检测） |
| DeFi 协议 | 流动性激励是否会导致恶性通胀 |
| L1/L2 公链 | 质押/验证者经济学是否合理 |
| GameFi | Play-to-Earn 经济循环是否闭合 |
| Meme 币 | 无需分析（无经济模型） |

## 在分析流程中的使用

### 调用时机

第五步基本面分析中，遇到以下情况时追加：
- 项目上线 < 6 个月（经济模型未经验证）
- 代币通胀率 > 10%/年
- 项目使用了复杂的多代币模型（如 veTokenomics）
- 用户明确要求深度代币经济分析

### 调用方式

```
/skill game-theory 分析 {项目名} 的代币经济模型
```

### 分析维度

1. **激励机制**：参与者的 Nash 均衡是什么？是否存在剥削性均衡？
2. **通胀/通缩**：代币供应量变化趋势，持有者稀释率
3. **价值捕获**：代币持有者如何从协议增长中获益？
4. **博弈漏洞**：是否存在闪电贷攻击、治理攻击、预言机操纵等博弈漏洞？
5. **MEV 风险**：协议设计是否引入额外的 MEV 攻击面？

### 结果解读

- 模型可持续 → 引用关键参数（通胀率、质押收益、费用分配）
- 模型有缺陷 → 以【经济模型风险】标注，说明具体缺陷
- 模型未经验证 → 标注"经济模型未经市场周期检验"
